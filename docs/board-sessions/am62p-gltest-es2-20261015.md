(PowerVR BXS-4-64).

All images were built from **`dc514010`** (HEAD8), a commit on `origin/main`

## Console port

The leased console port carried **main_uart0** this time. Check before any
build, as am62p-es2-r1c and am62p-es2-final-r2 did: a reader on the leased
port (the lease's serial console) while `echo YK-PROBE-S2 | sudo tee
/dev/ttyS2` and then `echo YK-PROBE-S3 | sudo tee /dev/ttyS3` ran over ssh.
The reader got **13 bytes, `YK-PROBE-S2\r\n`**; the ttyS3 probe did not
arrive. So the lease names the main_uart0 port now, and no other port of the
bridge was used.

The bridge takes one client, and the farm's console reader held it for the
whole lease: a second connection answered `busy: another client is
connected` (35 bytes), so `tools/am62p_netboot_uart.py capture` could not
connect. The runs used a **local relay** instead (outside the repository,
nothing of it committed): a small TCP server on the host that `BOARD_UART`
pointed at, fed with the console bytes copied from the lease's reader. So:

- `console.txt` / `console.ts` of each record hold the board's output as the
  lease's reader received it, with CR LF restored; the time stamps are when
  the relay delivered the bytes, not when the board printed them. The
  `back_after` of the GT and GM runs (594 s, 457 s) is inflated by the relay
  (the board itself was back at its login prompt within a few minutes).
- In the GM run, 1,696 consecutive identical lines (`I: gl_fb_target:
  framebuffer 1 incomplete (status 0x8cd6)`, refract) were relayed by count:
  the lease's reader showed them between byte offsets 448004 and 548068 with
  no other line between (100,064 bytes = 1,696 x 59).
- The first GT run (`20261015-1928-gt-dc514010-e34b1a38`) ended
  `verdict=no_spl` because the relay could not deliver its 131 KB console
  within board.sh's default 420 s bound; it is not a result. The board printed
  `gl_test: all: 0 of 50 cases failed` in that boot too. GT was rerun with
  `RUN_BOUND=3600 RETURN_BOUND=1800` (and GM with the same bounds).

are drawn without their texture (#1 terrain black, by the counters; nobody
looked at the panel). glmark2 counts both as ran because it never calls
`glGetError`. The `f2a13877` entry in RESULTS.md (same score) quotes neither
pool lines nor the counters (#13 came later), so these records cannot say
whether this is new.

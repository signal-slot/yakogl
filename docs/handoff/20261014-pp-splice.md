# pp-splice, 2026-10-14, plan #144

## State of main
- Preprocessor, ES 3.00 line continuation: nothing was wrong in
  `src/shaderc/online/{pp,lexer}.rs`. `lexer.rs` `splice_lines` already
  removes every backslash-newline before tokenizing (inside a directive name,
  identifier, number or operator) and restores the line count; ES 1.00 does not
  splice. `tests/es3_shaderc_pp.rs` pinned this with inline sources.
- The 4 "refused" dEQP programs (`line_continuation.preprocessing_token_*`,
  `.token_*`) were a harness fault. dEQP's `ShaderParser::parseShaderSource`
  resolves `\\` and then runs `removeExtraIndentation`, so the line after the
  backslash starts in column 0 (`#def\` + `ine`). `tests/es3_shaderc_corpus.rs`
  kept the indentation, which gave `#def            ine`, a correct refusal.
  The corpus now has `remove_extra_indentation`.
- Corpus, expected-pass built / refused (`tests/es3_shaderc_corpus.rs`,
  `DEQP_GLES3_TEST_DIR` = VK-GL-CTS `93bca018`): powervr 3453/8 -> 3457/4,
  vivante 3451/10 -> 3455/6, v3d 3457/4 after (base not run; the doc lists the
  same 4 refused). Every other column unchanged (fail-refused 2135, wrongly
  accepted 0). `preprocessor` row: 292 built, 0 refused.
- New `tests/es3_shaderc_pp_splice.rs`: the two dEQP bodies on both stages,
  the indented text still refused, lines after a splice, ES 1.00 unchanged.

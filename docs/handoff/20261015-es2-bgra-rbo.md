# report-es2 renderbuffer storage takes GL_BGRA_EXT again, 2026-10-15

Record: the dEQP-GLES2 final trees, `docs/board-sessions/pi4-es2-final.md` and
the i.MX8MP row of `docs/HANDOFF.md` at `835cf9cc` (46 new Fails, all
GL_BGRA_EXT renderbuffer cases of the `fbo` entry).

## State of main
`renderbuffer_format_advertised()` in `src/gl/framebuffer.rs` now takes
`GL_BGRA_EXT | GL_BGRA8_EXT` in one arm, listed with
`GL_EXT_texture_format_BGRA8888`. `tests/es2_bgra_rbo.rs` pins both names in
the `report-es2` and the default build: GL_NO_ERROR from
glRenderbufferStorage, storage allocated, framebuffer complete with either as
its only colour attachment. Without the arm line the report-es2 test fails.
ES 3.0 build behaviour is unchanged (`true` before the match).

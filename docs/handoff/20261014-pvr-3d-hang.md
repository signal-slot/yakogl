# pvr-3d-hang: the AM62P GLES3 "hang" on 3D linear_mipmap_linear, 2026-10-14, integration cd738b1a

Details: `tools/cts/log/investigations/pvr-3d-mipmap-hang.md`. Investigation
only (plan #144): no file under `src/` or `driver/` changed, no board run.

## Known defects

- **GLES3 hang** (no issue yet): change the entry to say that the cause is
  most likely **not a GPU hang** (hypothesis H1 of the investigation). On the
  host, the PowerVR back end gets bit-identical texture and sampler words
  for the 14th case (`linear_mipmap_linear`) and the 13th (`linear`, which
  finished), in both images, from the same program. A 3D texture is a
  one-level slice grid there, so the min filter never reaches the TPU. The
  board picture of a 3D mipmap case is wrong: level 0 only, and REPEAT lost
  on all three axes. dEQP's check of a wrong 3D `LINEAR_MIPMAP_LINEAR`
  picture is a six-deep search per pixel and took 337 s for one case on
  `c4ccc966` (`tools/cts/README.md` 2e). "The 14th case" in both images
  follows from dEQP's sorted case order (each image's third prefix,
  second filter). `no_reset` at 602/612 s cannot tell this from a hang,
  because the RTI resets up to 660 s after arming. Measured on the host
  with the PowerVR's picture (host Mesa forced to level 0 and clamped
  coordinates): every 3D `linear_mipmap_linear` case takes 8.8 to 18.8 s
  of dEQP checking, every other case under 0.07 s, and plain Mesa passes
  all in milliseconds. The board's 337 s case takes 18.8 s on the host
  (factor about 18), so both images reach case 14 at about 560 s and
  600 s. Not yet confirmed on the board: the investigation's section 7 has
  the check.
- The defect to fix behind it (no item yet): **PowerVR 3D textures sample
  level 0 only and lose REPEAT** (`src/gl/texture.rs`
  `texture_alloc_storage_3d`, `src/shaderc/online/powervr/select.rs`
  `vol_uv`). Mesa's path is the TPU's own 3D type (`TEXTYPE_3D`, 3D-twiddled
  layout, IMAGE_WORD1 `depth`, the full chain, `addrmode_w`). The
  investigation's section 3 compares the fields one by one.

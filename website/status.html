Reading the tables

  • dEQP-GLES2: the Khronos conformance tests for OpenGL ES 2.0, the 17,165-case mustpass list, run on Zephyr on the GPU. "Not supported" is an optional feature the board does not offer (for example 4x multisampling on the i.MX8MP); a warning is a quality warning, not a failure.
  • gl_test: YakoGL's own on-silicon suite (driver/tools/pvrlab/gl_test.c), numbered cases shared by the three boards, each reading its result back from the GPU.
  • glmark2-es2: 800x600, on-screen. Public scores come from Linux with the vendor or Mesa driver under different conditions (size, on- or off-screen, window system); driver/docs/glmark2.md lists them with their caveats.
  • Slint and the cluster: one Slint sample and the agl-slint-cluster demo, checked against a reference picture made on a PC at fixed points. The panels differ in size, so compare Mpx/s, not frames per second.
  • Boot: each board boots Zephyr from its own storage with no host and no network (docs/standalone-boot.md).

Not yet

From HANDOFF, "Known defects" and "Open work", as of main at the commit named in data.js. None of the fixes below is confirmed on a board from main.

Known defects

  • AM62P: 9 shaders.invariance.*.common_subexpression_* dEQP cases fail on a 2026-10-08 integration image and on the 32778b57 tree (2026-10-10). Fixed on main in e17fb6a7; image 1 of the AM62P tree on e17fb6a7 passes 1,379 / 0 (2026-10-10).
  • PowerVR: glmark2 shadow and refract sample a stale depth texture (pvr-depth-resolve, no issue yet). Root cause found on the host (a stale kick stamp); the host test is marked as an open defect; not fixed.
  • i.MX8MP: gl_test case 10 fails about one run in three (#9) and case 2 intermittently (#25). Cause not found.
  • i.MX8MP: 4x MSAA, gl_test case 16 (#8). The harness now skips the 4x half by name without a 4x config; the 4x path itself still fails, cause unknown.
  • Pi 4: 25 cube-map cases differ from the ES 2.0 reference images (#12). Fixed on the host; needs the Pi 4 run.
  • glmark2 terrain samples a black texture on every board (#1), AM62P refract's depth pass is refused (#2), Pi 4 refract and terrain do not fit the GPU carve-out (#4, #5). Fixed on the host, waiting for a board round.
  • i.MX8MP panel at its pixel clock (#23): the link is back at 69.3 MHz with a checked margin; viewing the panel by eye is pending.
  • GC7000 precompiled table lacks matattr (#22).

Open work

  • One confirming board session per board for every host-proved fix, including a whole dEQP-GLES2 tree on the AM62P.
  • OpenGL ES 3.0, host first: transform feedback capture, integer render targets, the new sampled formats, sRGB, occlusion queries, PowerVR 2D-array and shadow sampling; then the dEQP-GLES3 tree on each board.
  • Performance: not started.
  • Bare metal: src/osal/baremetal.c is a skeleton; no bare-metal boot is recorded yet.
  • The PowerVR driver's end-of-tile programs and boot self-test vertex shader are still Mesa's pco output; the GC7000 has no precompiled rows for most gl_test sources.
  • Design clean-up: debug knobs out of the product, the remaining C moved to Rust, names.
  • OpenGL ES 3.1 / 3.2 (#19).
  • Touch input for the demos: not yet planned.

Reading the tables

  • dEQP-GLES2: the Khronos conformance tests for OpenGL ES 2.0, the 17,165-case mustpass list, run on Zephyr on the GPU. "Not supported" is an optional feature the board does not offer (for example 4x multisampling on the i.MX8MP); a warning is a quality warning, not a failure.
  • gl_test: YakoGL's own on-silicon suite (driver/tools/pvrlab/gl_test.c), numbered cases shared by the three boards, each reading its result back from the GPU.
  • glmark2-es2: 800x600, on-screen. Public scores come from Linux with the vendor or Mesa driver under different conditions (size, on- or off-screen, window system); driver/docs/glmark2.md lists them with their caveats.
  • Boot: each board boots Zephyr from its own storage with no host and no network (docs/standalone-boot.md).

Not yet

Every open item and every known defect is a GitHub issue; this page names only the large ones, by stage of the roadmap. The full lists: known defects (open issues labelled bug) and all open issues.

  • Benchmarks (stage 2): the glmark2 pictures are checked per scene on the AM62P; the Pi 4 has no picture column yet and nobody has looked at the i.MX8MP panel (#1207). The README table is to come from one main commit on all three boards (#1196). On the AM62P, terrain and refract are slow (#1199, #1198); shadow is CPU time (#1006).
  • OpenGL ES 3.0 (stage 4): the AM62P tree again from current main (#1195), the remaining Pi 4 images (#1261), and a first i.MX8MP run (#1262).
  • Design: the PowerVR driver's own programs still come from Mesa's compiler (#1214); debug switches leave the product build (#1217); the original C moves to Rust (#1225); bare metal is a skeleton (#1223).
  • Release (stage 3): the contribution guide and README walkthrough re-run as written (#1264); the security contact (#1266).
  • Later: OpenGL ES 3.1 / 3.2 (#19), touch input (#24).

Try it

The steps as they work today. They are not yet checked on a clean machine.

On the PC: Linux, Python 3, the Zephyr SDK (1.0.1 was used), a nightly Rust toolchain, and Noto Sans fonts (the Slint compiler draws the text at build time).

1. The workspace

python3 -m venv .venv && . .venv/bin/activate && pip install west
west init -m https://github.com/signal-slot/yakogl --mr main yakogl-ws
cd yakogl-ws && west update
pip install -r zephyr/scripts/requirements-base.txt

2. The no_std Slint

Slint, femtovg and glow are patched to run without an OS. You make these trees once, from upstream sources plus the patches in driver/samples/zephyr/slint/nostd/. Its README.md has the exact commands (a Slint commit, then patch -p1). Call the results $SLINT_NOSTD and $NOSTD.

3. Build the Slint demo

# pick one board:  rpi_4b | verdin_am62p/am62p54/a53 | verdin_imx8mp/mimx8ml8/a53
west build -p always -b rpi_4b -d build/slint yakogl/driver/samples/zephyr/slint -- \
    -DSLINT_NOSTD_DIR=$SLINT_NOSTD -DNOSTD_PATCH_DIR=$NOSTD

AM62P only: first make the firmware header. You get the firmware yourself. This repository does not distribute it: it belongs to TI and Imagination.

  1. Take the firmware file from TI's Processor SDK for the AM62P. The file is named rgx.fw.36.53.104.796 (36.53.104.796 is the GPU version, BVNC). [TBD: the file's path inside the SDK is not documented here yet]
  2. Run the script on that file: 
    yakogl/driver/tools/mkfwblob.sh /path/to/rgx.fw.36.53.104.796
  3. The script writes driver/src/fw/pvr_fw_blob.h. The build needs this header. Never commit it.

Cluster demo: one sample for all three boards, driver/samples/zephyr/cluster (it also needs a clone of agl-slint-cluster). [TBD: build command]

4. Run it on the board

One runner for all three boards. It copies the image, boots it once, collects the log and the result, and waits until Linux is back.

export BOARD_HOST=user@your-board      # ssh login of the board's Linux
export BOARD_UART=...                  # Pi 4: serial device; AM62P: serial bridge host:port
export NETBOOT_SERVER=... NETBOOT_TFTP_ROOT=...   # Verdins: your TFTP server
tools/board.sh <board> status                     # board = pi4 | am62p | imx8mp
tools/board.sh <board> install                    # Verdins only: one U-Boot hook, once
tools/board.sh <board> run build/slint/zephyr/zephyr.bin logs/

Add --dry-run to see every command first; it touches nothing. tools/board.sh <board> uninstall removes the hook again.

How the board boots the demo

  • Raspberry Pi 4: the Pi firmware's tryboot starts the image once. The next boot is Raspberry Pi OS again.
  • Verdin AM62P and iMX8M Plus: a small hook in U-Boot. Linux sets a "run once" flag. U-Boot clears the flag first, then loads the image over TFTP and starts it. The next boot sees no flag and starts Linux.
The board always comes back to Linux. Every image arms a hardware watchdog before the demo starts (Pi 4: the PM watchdog; AM62P: the RTI; iMX8M Plus: WDOG1). The demo runs for a fixed time, then the board resets. If the demo hangs, the watchdog resets the board. Either way the next boot is Linux. The runner writes only the U-Boot hook and the run-once flag (Verdins), or the image and tryboot.txt on the boot partition (Pi 4), and removes the staged image after the run.

Performance

We measure performance with the standard benchmark glmark2-es2, never with the demo frame rates above. Every run is on-screen, in an 800x600 window, booted from the bootloader, on 2026-10-03 or 2026-10-04. All boards draw the same 800x600 window, so per pixel the scores compare directly. The last column is a public score of the same board under Linux. The conditions differ, so do not read the two columns as a contest.

  • Pi 4: the first row copies each frame with the CPU. The copy takes 91-99% of the frame in the 23 scenes where the GL work takes under 0.5 ms. In the second row the window is a view into the framebuffer, so there is no copy. The copy time is 0 in all 29 scenes, and the frame time is the V3D's own time.
  • Pi 4 not supported: two scenes need the buffer-map extension, which we do not offer. Two (shadow, refract) need the depth-texture extension, which the V3D driver does not offer.
  • AM62P failed scenes: shadow asks for a framebuffer with only a depth attachment, and we refuse it. Refract runs out of render pool memory.
  • AM62P not supported: two scenes need the buffer-map extension.
  • AM62P, the fence wait (316): the first row checks once per millisecond whether the GPU is done, so a frame waits up to 1 ms too long. Checking every 20 µs took about 100 µs off the light frames. The 20 µs wait is a build option, off by default.
  • AM62P, the swap drops depth/stencil (550): after a swap the window's depth and stencil buffers are undefined (EGL 1.5, section 3.10.1), so the frame no longer writes them out and the next frame no longer reads them back. That is about two thirds of the memory a light frame moved. This is the default for window surfaces.
  • iMX8M Plus: the first run. The scan-out view removes the copy of each frame to the panel (39 to 46), but every frame still costs about 24 ms, and that floor is not the copy. Finding it is the next item. The board has no console, so the score comes back in the result record and per-scene numbers are not read.
  • The public numbers differ in size, window system, driver and OS. TI's size is not stated. The score also leaves out scenes that do not run.

Where the PowerVR's frame time goes

On the AM62P, the GPU's fragment phase costs about 121 µs per frame plus 0.37 µs per 16x16 tile, measured over four window sizes (200x150 to 1600x900). A frame that draws nothing but the clear still costs about 0.26 µs per tile, about 1 ns per pixel: most of one full-screen pass. There is no cheaper clear to switch to: like Mesa's driver, YakoGL clears with the GPU's background object, not with a drawn quad. Splitting the rest needs the GPU firmware's own timestamps (HWPerf), which is the next instrument.

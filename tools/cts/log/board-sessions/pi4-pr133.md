## Board

The leased Pi 4 answered over ssh (`uname`: Linux 6.12 aarch64). The dry run of
`tools/board.sh --dry-run pi4 run <img-pi4-206> … c206-066a2db8` passed: image
check ok (footprint 91643904, sha256 prefix `5d440bc943c78b57`), tryboot
backend, serial capture on the bridge. The real run stopped at once:
`BOARD_HOST` is not in the worker's environment, and setting it on the command
line (`BOARD_HOST=<lease login> tools/board.sh …`, also via `env`) was refused
("requires approval"). After `tools/board.sh` itself was allowed, the plain
command ran and printed `uboot-netboot-lib.sh: line 70: BOARD_HOST: set
BOARD_HOST=user@host of the board`; the variable can only be given in the
command line, which needs approval. So `board.sh` never touched the board: no staging, no
tryboot, no reboot. Recoveries 0, reboots 0, GL clients 0 — nothing ran, so
these zeros say nothing about the GPU.

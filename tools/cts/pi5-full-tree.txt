# The whole dEQP-GLES2 tree for the Raspberry Pi 5 (driver/samples/zephyr/deqp,
# board rpi_5, the 7.1 table) in 31 images, one CONFIG_DEQP_CASE per line, the
# format of pi4-full-tree.txt (blank lines and '#' lines are skipped).
# Each line is preceded by "# image <LABEL>: <mustpass names it selects>".
# It starts as a copy of pi4-full-tree.txt's 29 images, and two blocks are
# re-cut where docs/notes/rpi5-deqp-glmark2.md section 4 says the block mixes
# cases whose 7.1 features arrive at different times:
#   T1 (181) -> T1 (41: texture.completeness, format, wrap) and T1V (140:
#       texture.vertex): vertex texture fetch is a separate open item of the
#       7.1 table, so T1V can fail on it without hiding the 41 cases that
#       need only the sampled-texture wiring.
#   MISC (70) -> MISC (60: depth_stencil_clear, multisample, lifetime: Z/S
#       clear and the multisample refusal, both already in the table) and PO
#       (10: polygon_offset: the polygon-offset reference is open).
# Blocks FB1/FB2 and F1 are kept as the Pi 4 has them: each mixes cases that
# need the same open item (render targets below 8 alpha bits; blend and
# depth/stencil references). Every one of the 17165 names of
# gles2-mustpass.txt is selected by exactly one line.
#
# Image T5 needs driver/samples/zephyr/deqp/texture-2048.conf
# (-DEXTRA_CONF_FILE=texture-2048.conf), as on the Pi 4. Every other image
# uses boards/rpi_5.conf as it is.

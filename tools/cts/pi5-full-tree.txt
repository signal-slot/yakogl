# The whole dEQP-GLES2 tree for the Raspberry Pi 5 (BCM2712, V3D 7.1;
# driver/samples/zephyr/deqp, board rpi_5) in 31 images, one CONFIG_DEQP_CASE
# per line, the form of pi4-full-tree.txt: each filter line is preceded by
# "# image <LABEL>: <mustpass names it selects>", the label of the records
# (record_SW<n>_<LABEL>.txt). Every one of the 17165 names of
# gles2-mustpass.txt is selected by exactly one line
# (tools/cts/check-gles3-tree.py --mustpass tools/cts/gles2-mustpass.txt).
# Built by tools/cts/pi5-deqp-images.sh (deqp-tree-images.sh rpi_5).
#
# It starts as the Pi 4's 29 images (pi4-full-tree.txt), same labels and
# filters, re-cut only where a Pi 4 image mixes cases whose 7.1 features
# arrive at different times (docs/notes/rpi5-deqp-glmark2.md, sections 4
# and 6): an image whose missing feature hangs or refuses everything costs a
# whole lifetime and hides the cases of the image that could run. Two re-cuts:
#
# - T1 (181 on the Pi 4) -> T1 91 + TV 90: texture.vertex (vertex texture
#   fetch) is its own open item at 7.1, after the fragment-side texture
#   wiring (P10: texuni71, mip71, the OSAL TFU) that completeness, format
#   and wrap need.
# - MISC (70 on the Pi 4) -> MISC 60 + PO 10: polygon_offset waits for the
#   7.1 polygon-offset reference (open), while depth_stencil_clear,
#   multisample and lifetime belong to the first board run (item 10:
#   SMALL, FF, MISC, on the clear plan and readback the table already has).
#
# The other 27 images are the Pi 4's: each one's cases wait for the same
# 7.1 piece (section 4: F1 on refs71b/compose71d, FB1/FB2 on the
# fewer-than-8-alpha-bits answer and the P10 wiring, H on points/lines,
# the S/D/E/AL/U1/LA images on link71 and the uniform fill).
#
# Image T5 needs driver/samples/zephyr/deqp/texture-2048.conf
# (-DEXTRA_CONF_FILE=texture-2048.conf), as on the Pi 4. Its carve-out and
# tiled-copy sizes are the Pi 4's measured values, not yet measured on the
# Pi 5 (section 3.3).

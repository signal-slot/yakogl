# The PowerVR USC documentation table and its verification decoder

`pco_isa_extract.py` reads Mesa's `pco_isa.py` from a local Mesa tree and
writes `docs/online-shaderc/isa/usc-isa.json`, the table behind
`docs/online-shaderc/isa.md`; `usc_decode.py --blobs` decodes the driver's
four hand-verified USC programs (`driver/src/pvr_usc_*_blob.h`) through that
table and is the gate on it — 4 of 4, every byte accounted for. Nothing of
Mesa's is copied here: the extractor records the inputs' SHA-256 and the MIT
attribution in the JSON header.

**This table is documentation and verification, not a codec source.** The
shipping decoder and encoder (`src/shaderc/online/powervr/`) are generated by
`tools/pco-isa/`, which is a second, independent reading of the same
declarations; the two were compared field for field and disagree about nothing
(`tools/pco-isa/crosscheck.py`: *0 disagreements about the encoding*). Do not
generate a codec from `usc-isa.json` as it stands: it records a form's
explicitly pinned fields and its settable ones but **not which reserved fields
the form pins**, so a generated codec would neither check those bits when
decoding — which is where an ambiguous parse comes from — nor write them when
encoding, and would survive today only because every reserved value in this
ISA happens to be zero. It also has **no `pco_map.py` half**: no operation
names and no phase tables, and the same instruction form is a different
operation in a different phase.

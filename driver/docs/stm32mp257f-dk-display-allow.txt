# Bits of the STM32MP257F-DK display registers (LTDC, DSI host and ST wrapper,
# the RCC and SYSCFG display registers) that may differ between the Rust
# drivers (the model's image after the LTDC, DSI and ADV7535 bring-up of
# driver/rust/src/ip/{stm32_ltdc,dw_mipi_dsi,stm32_dsi_phy,adv7535}.rs) and
# the Linux dump the board task takes (stm32mp257f-dk-display-dump-linux.txt,
# written by tools/probes/stm32mp257f_dk/linux_display_dump/).
# Format: ADDRESS MASK REASON (hex, hex, text), as am62p-display-allow.txt and
# x2-hdmi-allow.txt. MASK is the set of bits allowed to differ.
#
# Seeded before the dump exists: the entries below follow from what the
# registers are (status, IRQ, counter and position registers, the frame
# buffer addresses), not from a comparison. Entries the first comparison
# finds are added below them with the RM0457 section that explains each, or
# the driver changes instead. Section numbers are not given where RM0457 has
# not been read (docs/notes/stm32mp257f-dk-display.md, "RM0457 is unread"):
# the register is named and the chapter is the LTDC or DSI one.
#
# Sources of the offsets (L = Linux drivers/gpu/drm/stm, drm/bridge):
#   LTDC  ltdc.c:69-94 (global block), :461-505 (layer table of the 40100
#         family, layers at 0x100 + 0x100 * n), docs/notes/stm32mp257f-dk-display.md
#   DSI   bridge/synopsys/dw-mipi-dsi.c (host map), dw_mipi_dsi-stm.c:37-107
#         (ST wrapper at 0x400, DSI_PCTLR 0xa0, DSI_PSR 0xb0, DSI_PTCR0 0xb4)
#
# --- The read list (read by the Linux dump script, read only) ---
# One line per block, in the form
#   #@read ADDRESS WORDS NAME     WORDS consecutive 32-bit words from ADDRESS
#   #@name ADDRESS NAME           the name of one word, else NAME+0xOFFSET
# The bases are ST's device trees: LTDC display-controller@48010000
# (stm32mp251.dtsi:2150), DSI host and wrapper 0x48000000
# (stm32mp255.dtsi:123-133), RCC 0x44200000, SYSCFG 0x44230000.
# Left out on purpose, because a read changes hardware state (the FIFO pop
# and read-to-clear are the DWC DSI host's documented behaviour; dw-mipi-dsi.c
# reads GEN_PLD_DATA only in dw_mipi_dsi_read and INT_ST0/1 only in
# dw_mipi_dsi_clear_err; no I2C or GPIO register is read, the ADV7535 goes
# through regmap debugfs):
#   DSI_GEN_PLD_DATA 0x48000070 (a read pops the receive FIFO),
#   DSI_INT_ST0 0x480000bc and DSI_INT_ST1 0x480000c0 (read-to-clear in
#   dw-mipi-dsi.c, which reads them to clear the flags).
# Out of the list until the offsets are pinned (soc::stm32mp2 display ids):
#   the RCC FLEXGEN/XBAR registers behind FLEXGEN_27, FLEXGEN_28 and
#   ICN_DISPLAY (those clocks are SCMI's, OP-TEE's), the DSI PHY test
#   registers beyond DSI_PTCR0/1.
# The RIFSC base 0x42080000 (bus@42080000, stm32mp251.dtsi, reg 0x1000) and
# its layout are confirmed against ST's sources: SECCFGRx 0x10 + 4x, PRIVCFGRx
# 0x30 + 4x, RCFGLOCKRx 0x50 + 4x (x = id / 32, bit id % 32), PERn_CIDCFGR
# 0x100 + 8n, PERn_SEMCR 0x104 + 8n (L drivers/bus/stm32_rifsc.c
# RIFSC_RISC_SECCFGR0/PRIVCFGR0/PER0_CIDCFGR/PER0_SEMCR, which reads them
# from the non-secure side for its debugfs; O core/drivers/firewall/
# stm32_rifsc.c _RIFSC_RISC_SECCFGR0 0x10, _PRIVCFGR0 0x30, _RCFGLOCKR0 0x50,
# _PER0_CIDCFGR 0x100, _PER0_SEMCR 0x104, _OFFSET_PERX_CIDCFGR 0x8, tag
# 4.0.0-stm32mp-r3.1). The ids are the access-controllers of stm32mp251.dtsi
# and stm32mp255.dtsi: I2C2 42, LTDC cmn 80, DSI 81, LTDC l1l2 119, l3 120,
# rot 121 (RCC itself is 156). A refused read is reported as ERR and does not
# stop the dump.
# RCC_LTDCCFGR 0x840 and RCC_DSICFGR 0x844 are L drivers/clk/stm32/
# stm32mp25_rcc.h (RCC_I2C2CFGR 0x7a8, FINDIV0..63CFGR 0x1224..0x1320, XBAR0..
# 63CFGR 0x1018..0x1114 are not read). SYSCFG_DISPLAYCLKCR 0x5000, mask 0x3
# is L drivers/clk/stm32/clk-stm32mp25-syscfg.c; SYSCFG is syscon@44230000.
# Only the registers Linux's drivers name are read in the DSI blocks (no
# reserved or undocumented offset, so no read can fault); DSI_WIER 0x408 and
# DSI_WIFCR 0x410 are the STM32 DSI wrapper's, not named by dw_mipi_dsi-stm.c.
#
# LTDC global block 0x00-0x90 (IDR, LCR, SSCR ... FUT), then layers 1 to 3.
#@read 0x48010000 37 LTDC
#@name 0x48010000 LTDC_IDR

#@name 0x48010008 LTDC_SSCR

#@read 0x48010100 32 LTDC_L1

# RCC: the two display gates and resets (RCC_LTDCCFGR 0x840, RCC_DSICFGR 0x844,
# docs/notes/stm32mp257f-dk-display.md, "Clocks, resets, power and RIF").
#@read 0x44200840 2 RCC
#@name 0x44200840 RCC_LTDCCFGR
#@name 0x44200844 RCC_DSICFGR

# 1 clk_pix_lvds, 2 ck_ker_ltdc).
#@read 0x44235000 1 SYSCFG_DISPLAYCLKCR
# RIFSC: SECCFGR0-3, PRIVCFGR0-3, LOCKR0-3; then CIDCFGR/SEMCR of entry 42
# (I2C2), 80 (LTDC common), 81 (DSI), 119 (LTDC l1l2), 120 (l3), 121 (rot).
#@read 0x42080010 4 RIFSC_SECCFGR
#@read 0x42080030 4 RIFSC_PRIVCFGR
#@read 0x42080050 4 RIFSC_RCFGLOCKR

# --- Allow-listed bits ---

# LTDC interrupt and status (RM0457, LTDC chapter, "LTDC_ISR", "LTDC_CDSR",
# "LTDC_CPSR", "LTDC_CCRCR"): events and positions sampled at an arbitrary time.
0x48010038 0xffffffff LTDC_ISR: pending events (line, FIFO underrun, transfer error, register reload, CRC)
0x48010048 0x0000000f LTDC_CDSR: VDES/HDES/VSYNCS/HSYNCS, the display status at the moment of the read
0x48010044 0xffffffff LTDC_CPSR: current X and Y position, a counter
0x4801007c 0xffffffff LTDC_CCRCR: CRC of the pixels so far, depends on the picture and the moment
0x48010090 0xffffffff LTDC_FUT: FIFO underrun threshold, ours against Linux's (ltdc.c:267 default 128)

# LTDC layer registers: the buffers are Linux's against ours; RCR carries the
# self-clearing reload bits (IMR bit 0, VBR bit 1; ltdc.c:254).
0x48010108 0x00000003 LTDC_L1RCR: reload request bits clear themselves
0x48010134 0xffffffff LTDC_L1CFBAR: Linux's frame buffer against ours
0x48010208 0x00000003 LTDC_L2RCR: likewise
0x48010234 0xffffffff LTDC_L2CFBAR: likewise
0x48010308 0x00000003 LTDC_L3RCR: likewise
0x48010334 0xffffffff LTDC_L3CFBAR: likewise

# DSI host (the DesignWare map, dw-mipi-dsi.c): status the link reports at
# the moment of the read. The lock bit (bit 0 of DSI_PSR, PHY_STATUS in the
# generic map) is NOT allowed to differ, only the lane states are.
0x480000b0 0xfffffffe DSI_PSR: lane and direction status bits, stop states and ULPS sampled; PHY lock must match
0x48000074 0xffffffff DSI_CMD_PKT_STATUS: command FIFO empty/full flags, sampled

# DSI ST wrapper (dw_mipi_dsi-stm.c): interrupt and PLL status flags.
0x4800040c 0xffffffff DSI_WISR: wrapper interrupt status flags, sampled (PLL lock/unlock events)

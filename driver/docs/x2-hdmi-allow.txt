# Bits of the Armadillo-X2 HDMI registers that may differ between the
# Zephyr cold path (the model's image after hdmi_chain::bring_up) and the
# Linux dump (x2-hdmi-dump-linux.txt), each with its reason.
# Format: ADDRESS MASK REASON (hex, hex, text). See
# driver/rust/src/soc/imx8mp/hdmi_golden.rs and driver/docs/x2-hdmi-cold.md.
#
# Seeded before the dump exists: the entries below are differences that
# follow from what the registers are, not from a comparison. Entries found
# by the first comparison are added below them with the RM section that
# explains each, or the driver changes instead.

# LCDIF3 (IMX8MPRM Rev. 3 13.3.3.1)
0x32fc6024 0xffffffff INT_STATUS_D0: event flags (VSYNC, UNDERRUN...), write-1-to-clear, sampled at an arbitrary time
0x32fc6030 0xffffffff INT_STATUS_D1: panic event flag, likewise
0x32fc620c 0xffffffff CTRLDESCL_LOW0_4: the frame buffer address, Linux's buffer against ours
0x32fc6210 0x0000000f CTRLDESCL_HIGH0_4: the frame buffer address bits 35:32, likewise

# HDMI TX block control (13.11.3.1.15)
0x32fc0230 0x0000001f TX_STATUS0 TX_PHY_AFC_CODE: the PLL's automatic frequency calibration result, analog

# HDMI TX PHY (13.10.3.1.35)
0x32fdff88 0x0000000f PHY_REG34 AFC code: likewise

# HDMI TX controller (13.9.3.9.6)
0x32fdc006 0x000000ff mc_lockonclock_1: sticky clock-present flags, write-1-to-clear; ours are cleared by the video check
